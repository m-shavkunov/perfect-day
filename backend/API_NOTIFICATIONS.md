# Документация email-уведомлений

## Назначение

Система email-уведомлений отправляет пользователю напоминания о предстоящем начале запланированных задач.
Отправка выполняется автоматически в фоновом режиме, без необходимости вручную обращаться к API.

## Принцип работы

Для автоматической проверки используется APScheduler.

Основной процесс:

1. При запуске FastAPI запускается фоновый планировщик.
2. Каждую минуту система проверяет ближайшие задачи в расписаниях пользователей.
3. Если до начала задачи осталось 15 минут, формируется уведомление.
4. Система отправляет письмо на электронную почту пользователя.
5. Результат отправки сохраняется в базе данных.

## Содержание письма

Письмо содержит:

- напоминание о скором начале задачи;
- название задачи;
- время начала;
- дату выполнения;
- подпись приложения «Идеальный День».

Пример текста:

```text
Напоминаем, что через 15 минут начнётся задача:

Подготовить отчёт

Начало: 10:00
Дата: 21.11.2026

Хорошего дня!
Идеальный День
```

## Настройка SMTP

Для отправки писем используется SMTP-сервер Gmail.

Параметры подключения задаются в файле `.env`:

| Переменная | Назначение |
|---|---|
| `SMTP_HOST` | Адрес SMTP-сервера |
| `SMTP_PORT` | Порт SMTP-сервера |
| `SMTP_USER` | Почтовый аккаунт отправителя |
| `SMTP_PASSWORD` | Пароль приложения |

Используемые параметры:

- SMTP-сервер: `smtp.gmail.com`;
- порт: `465`;
- подключение: SSL.

Секретные данные хранятся в `.env` и не должны попадать в Git-репозиторий.

## Хранение уведомлений

Для учёта отправок используется модель `Notification`.

Она содержит следующие данные:

| Поле | Назначение |
|---|---|
| `id` | Идентификатор уведомления |
| `schedule_item_id` | Элемент расписания, к которому относится уведомление |
| `status` | Статус отправки |
| `attempts` | Количество попыток отправки |
| `last_error` | Последняя ошибка отправки |
| `sent_at` | Время успешной отправки |

Для одного элемента расписания предусмотрена уникальная запись уведомления. Это предотвращает повторную отправку уже успешно отправленного напоминания.

## Повторные попытки

Если отправить письмо не удалось, система сохраняет информацию об ошибке и может повторить отправку.
Предусмотрено не более трёх попыток.

После успешной отправки уведомление получает статус `sent`, а время отправки сохраняется в базе данных.

## Проверка работы

Работа системы проверяется двумя способами:

1. Тестирование функции отправки email.
2. Проверка автоматической отправки через APScheduler при работающем FastAPI.

При успешной отправке в базе данных фиксируются статус `sent`, количество попыток и время отправки.

## Важные особенности

- Проверка задач выполняется автоматически каждую минуту.
- Напоминание отправляется за 15 минут до начала задачи.
- Время работы планировщика настроено на часовой пояс `Asia/Yekaterinburg`.
- Для отправки используется email пользователя.
- SMTP-пароль не хранится в исходном коде проекта.
