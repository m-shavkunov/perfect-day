# API настроек пользователя

## Назначение

API настроек позволяет пользователю задавать индивидуальный режим рабочего дня. Эти параметры используются планировщиком при автоматическом распределении задач.

Настройки хранятся отдельно для каждого пользователя.

## Endpoints

### 1. Получение настроек

**GET `/settings/`**

Возвращает текущие настройки авторизованного пользователя.
Параметры запроса отсутствуют.

Пример ответа:

```json
{
  "work_start": "09:00:00",
  "work_end": "18:00:00",
  "lunch_start": "13:00:00",
  "lunch_end": "14:00:00",
  "break_duration_min": 10,
  "work_before_break_min": 50,
  "id": 1,
  "user_id": 1
}
```

### 2. Обновление настроек

**PUT `/settings/`**

Обновляет настройки рабочего дня авторизованного пользователя.

Пример тела запроса:

```json
{
  "work_start": "08:00:00",
  "work_end": "17:00:00",
  "lunch_start": "12:00:00",
  "lunch_end": "13:00:00",
  "break_duration_min": 15,
  "work_before_break_min": 60
}
```

Пример ответа:

```json
{
  "work_start": "08:00:00",
  "work_end": "17:00:00",
  "lunch_start": "12:00:00",
  "lunch_end": "13:00:00",
  "break_duration_min": 15,
  "work_before_break_min": 60,
  "id": 1,
  "user_id": 1
}
```

## Описание полей

| Поле | Тип | Назначение |
|---|---|---|
| `work_start` | time | Начало рабочего дня |
| `work_end` | time | Окончание рабочего дня |
| `lunch_start` | time | Начало обеда |
| `lunch_end` | time | Окончание обеда |
| `break_duration_min` | integer | Продолжительность перерыва в минутах |
| `work_before_break_min` | integer | Время работы до перерыва в минутах |
| `id` | integer | Идентификатор настроек |
| `user_id` | integer | Идентификатор пользователя |

## Использование в планировщике

При генерации расписания планировщик учитывает заданные настройки:

- Начало и окончание рабочего дня определяют доступный временной интервал.
- Обед исключается из времени распределения задач.
- Перерывы автоматически добавляются после заданного количества минут работы.
- Настройки применяются к расписанию конкретного пользователя.

## Авторизация и ошибки

Для работы с настройками требуется авторизация пользователя.

Основные ответы API:

- `200 OK` - запрос выполнен успешно.
- `401 Unauthorized` - пользователь не авторизован.
- `422 Unprocessable Entity` - переданы некорректные данные.

Документация API также доступна через Swagger UI по адресу `/docs` при запущенном бэкенд-сервере.
